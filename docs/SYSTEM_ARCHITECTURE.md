# 内容创作系统架构

```text
选题调研 ─→ 写稿 ─→ 剪辑 ─→ 封面 ─→ 发布
 planned     planned   partial   planned   planned
                         │
                         ├─ prepare
                         ├─ preview
                         ├─ render
                         └─ verify
```

每个阶段未来都通过明确的 JSON/Markdown 交接物连接，而不是依赖某一个模型的聊天历史。

## 事实源

一条视频对应一个任务单。任务单记录输入、确认过的表达、场景时间线、视觉模板、字幕和输出要求。Agent 可以提出修改，但确定性工具只执行任务单里已写明的内容。

## 模型与执行器分工

| 角色 | 负责 | 不负责 |
|---|---|---|
| Codex / Claude / DeepSeek | 理解口播、设计表达、填写任务单、审查预览 | 偷偷发布、虚构验收 |
| Remotion | 按任务单生成画面 | 判断观点是否正确 |
| FFmpeg / FFprobe | 音轨封装、抽帧、规格与解码验收 | 语义剪辑 |
| 人 | 确认删改、素材授权、最终审美、发布 | 被迫逐帧手工搭基础版式 |

## 模块成熟度规则

只有完成真实输入、可重复运行、失败可见、结果可验收四项，模块才允许进入 `skills/`。尚未满足的能力只进入 `ROADMAP.md`。
